## Known security gaps (Priority One — update pipeline)

Confirmed by inspecting `Services/UpdateService.cs`, `Core/Update/ManifestSignatureVerifier.cs`, `Core/Update/UpdateSecurityValidator.cs`, `Core/Update/PatchIntegrityVerifier.cs`, `Core/Update/UpdateDownloader.cs`:

1. **Placeholder signing key** — `ManifestSignatureVerifier.PublicKeyBase64` = `"MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE"` is truncated (~18 bytes; a real P-256 SPKI is ~91 bytes). Not a real provisioned key.
2. **Manifest signature never verified in live path** — `DownloadAndApplyUpdateAsync` never calls `ManifestSignatureVerifier`.
3. **Authenticode never verified in live path** — `DownloadAndApplyUpdateAsync` never calls `TryVerifyAuthenticode`, never checks publisher identity.
4. **Self-verification bug** — `VerifyStagedArtifact(stagedPath, actualSha, fi.Length)` compares the file's actual hash/size against itself (always passes), not against the manifest's expected values.
5. **Size check disabled** — `expectedSize` passed as `0` to `DownloadAsync`.
6. **No max download size limit** — `UpdateDownloader.DownloadAsync` has no `MaxDownloadSize` enforcement.
7. **No redirect validation** — `HttpClient.GetAsync` follows redirects by default; `UpdateSecurityValidator` checks the initial URL only, not the final URI after redirects.
8. **No staging ACL hardening** — `%ProgramData%\Deltempo\Updates\` created with default ACLs.
9. **No positive-path signature test** — all `ManifestSignatureVerifierTests` are negative-only; no test signs with a real test key and verifies.
10. **No key rotation / kid handling** — manifest has no key identifier field.
